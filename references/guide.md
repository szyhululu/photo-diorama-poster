# 使用手册：槽位提炼 · 变体 · 工具适配 · 排错

母版提示词在 `references/prompt-zh.txt` 与 `references/prompt-en.txt`，占位符由
`scripts/build_prompt.py` 填充。本文件说明「填什么」和「出问题怎么办」。

---

## 一、占位符清单

| 占位符 | 由脚本生成 | 说明 |
|---|---|---|
| `{{ASPECT}}` | ✅ 自动 | 画幅词：`3:4 竖版` / `1:1 方形` / `4:3 横版` / `16:9 宽幅` |
| `{{AXIS}}` `{{DIM}}` `{{UP}}` `{{DOWN}}` | ✅ 自动 | 分区轴：上下/高度/上区/下区，或 左右/宽度/左区/右区 |
| `{{EDGE}}` `{{EDGE_EN}}` | ✅ 自动 | 标题落点：`紧贴水平分界线下方` / `紧贴垂直分界线右侧` |
| `{{TITLE}}` | 参数 `--title` | 英文标题，2–4 词；默认编辑体句式大小写（`Pasture`），`--uppercase` 才转全大写 |
| `{{SUBJECT_BLOCK}}` | 参数 `--subject` | 主体锚定段，防止上下两区主体跑偏 |
| `{{PALETTE_BLOCK}}` | 参数 `--palette` | 色彩锚定段，防止模型滑向固定色系 |
| `{{NOTES_SENTENCE}}` | 参数 `--notes` | 微型注释；`--notes -` 或 `--no-notes` 可整段省略 |
| `{{EXTRA_BLOCK}}` | 参数 `--extra` | 追加要求 |

脚本只依赖 Python 标准库，任何装了 python3 的机器都能跑；模板文件缺失或占位符没填满会直接报错退出，不会静默产出半成品提示词。

改模板时注意：母版里有一组**用实测失败换来的硬约束**（30° 轴测、两种媒介、文字不压照片、层叠纸板基座、禁止扁平矢量），脚本每次运行都会检查它们是否还在（`REQUIRED_MARKERS`），少了会打 `[warn]`。改措辞后请重跑一次确认没有告警。

## 一·五、下区到底长什么样（务必先对齐这个心智图像）

这是整个 skill 最容易做错的地方，也是最容易左右摇摆的地方。**下区不是插画，是一个实体微缩模型（diorama）的照片级呈现**：

| 要素 | 正确 | 错误 |
|---|---|---|
| 媒介 | 哑光的**实体微缩模型**：有真实体积、棚拍柔光、柔和接触阴影、纸张颗粒 | ① 扁平矢量插画（描边色块）② 原照片的直接复制 |
| 基座 | 一块**很薄的层叠纸板**，侧面露出**一层层纸页般的叠压纹理**，整体呈等距矩形 | 厚基座、石块、无基座、漂浮的地面 |
| 板顶面 | 就是**原照片那块地形**：保留山坡起伏轮廓、草地、树木与主体的相对位置 | 简化成一块平板草地，或换一处风景 |
| 背景 | **纯净近白纸色**，几乎无可见纹理，四周大面积留白 | 灰底、渐变底、有场景的影棚 |
| 阴影 | 板下**一层收敛的接触阴影**，紧贴轮廓，不扩散 | 戏剧化长投影、弥散大阴影、无阴影 |
| 文字 | 细体现代**衬线**，首字母大写（`Pasture`）；标题与编号之间**拉开明显水平间距** | 全大写无衬线、标题与编号紧贴、文字压在上方照片上 |

**两个方向都要防**：既不能让它退回平视扁平插画，也不能让它照抄成照片。真正把两者分开的是「**近白影棚背景 + 薄纸板基座 + 哑光材质 + 禁止景深/虚化/噪点**」这四条，**不是**「把它画成扁平插画」。（历史上有人把它写成「必须是扁平矢量编辑插画」，结果下区一路偏成平视扁平插画——方向错了。）

## 二、怎么从照片里提炼四个槽位（本 skill 的核心手艺）

拿到照片后先看图，再落笔。不要跳过这一步直接调用生成——槽位质量决定成品质量。

### 1. `--subject`：一句话锁定主体

结构固定为「**谁/什么 + 在哪 + 什么姿态/朝向**」，一到两个分句，不写形容词堆砌。

- 好：`一位老渔民站在木质小船上，面朝左侧，右手扶着船桨`
- 差：`一个很有故事感的老爷爷，氛围宁静`（无法约束两区一致性）

### 2. `--palette`：3–5 个色，按深浅排列

从原图取色，**不要凭印象写颜色名**。做法：看图说出 3–5 个最代表性的色相，按「最深 → 中间 → 最亮」排序，并保留冷暖关系。

- 好：`深靛蓝 / 雾灰蓝 / 暖沙白 / 氧化铜绿`
- 差：`莫兰迪色系`（等于没给，模型会自己编）
- 差：`蓝、黄、红`（未提纯，容易滑向高饱和）

### 3. `--title`：2–4 词英文标题

从**地点 / 动作 / 状态 / 情绪**里挑一个支点，名词性短语，不加感叹号，参考独立杂志封面标题。
默认按编辑体写成**句式大小写**（`Pasture`、`Still Waters`），这也是参照样张的写法；确实需要全大写冲击力时再加 `--uppercase`。

| 照片内容 | 可用标题方向 |
|---|---|
| 海边孤舟、退潮 | `Still Waters` / `Low Tide` |
| 山路骑行 | `Northbound` / `Long Climb` |
| 老厂房、停机设备 | `Idle Plant` / `Shift Over` |
| 人像、窗口侧光 | `Half Light` / `Room 03` |
| 牧场、牛群吃草 | `Pasture` / `Grazing Light` |

规避：`Beautiful Day`、`Wonderful Life` 这类形容词句；以及超过 5 个词的长句（模型排版会糊）。

### 4. `--notes`：微型注释

一行以内的编号 / 年份 / 地名 / 极短短语，例如 `No.03 / 2024 PORTLAND`、`PLATE 11`。
不需要就传 `--notes -` 关掉，比让模型自由发挥更安全。

## 三、变体矩阵

| 场景 | 参数 | 说明 |
|---|---|---|
| 默认竖版海报 | `--variant vertical`（默认） | 3:4，上下 1:1，最贴合原始设定 |
| 横构图照片 | `--variant landscape --layout leftright` | 左右 1:1，避免主体被压扁在窄条里 |
| 首页 / 封面方图 | `--variant square` | 1:1，上下 1:1 |
| 视频封面 / 头图 | `--variant wide --layout leftright` | 16:9，左右 1:1 |
| 不要文字 | 加 `--no-notes` 并在 `--extra` 写「不要任何文字与编号」 | 有些模型不写标题会更干净 |
| 需要中英双语输出 | `--lang both` | 同时产出中英母版，便于喂不同模型 |

**主体类型微调建议**（写进 `--extra`）：

- **人像**：补一句「下区保留发型轮廓与服装剪影这两个识别特征」
- **建筑**：补一句「下区保留屋顶结构与立面开窗节奏，其余体块概括」
- **产品/静物**：补一句「下区保留轮廓转折与材质对比，去掉全部 Logo 与文字」
- **群像/多人**：补一句「下区仅保留 3–5 个主要人物剪影，其余淡出」

## 四、工具适配：任何 Agent 都能用

这个 skill 不绑定任何图像工具，只要求一项能力：**能根据提示词产出 3:2 或 3:4 图像**。按下表落地：

### 先选路线（决定后面所有步骤）

| 路线 | 做法 | 上区保真 | 下区能否成模型 | 结论 |
|---|---|---|---|---|
| **A · 一次图生图出整张** | 原图 + 整份提示词交给图生图 | ★★★ 保真度高时几乎等同原图 | ★★★ 可以——前提是母版里「近白影棚底 + 薄纸板基座 + 哑光 + 禁止景深」四条都在 | **首选** |
| **B · 裁切 + 合成** | 上区裁原图（零生成）＋ 下区生成 ＋ 本地拼接 | ★★★ 原始像素 | ★★ 取决于提示词；且下区地形无法与原图精确对应 | 备选 |

**为什么路线 A 是首选**：下区的板顶面要**沿用原照片那块地形**（山坡起伏、树木与主体的相对位置），这只有把原图交给模型才做得到；纯文生图只能画一块"像样"的草地。

**为什么路线 A 一度被判死**：早期母版只写了「下区重构为等距插画」，没给出"变成模型"的机制，模型手里有原图就直接照抄，下区退化成照片的写实复制。当时的错误归因是「给了参考图就会照抄」，于是把下区改成扁平矢量插画——方向就偏了。真正的分界不在"要不要给参考图"，而在**背景与基座**：近白影棚底 + 薄纸板 + 哑光 + 禁止景深。这四条写死后，图生图能同时做到"上区保真"和"下区模型化"。

**路线 B 什么时候用**：宿主图生图保真度完全不可控（下区反复写成照片）、或用户就是要一块干净、脱离原图细节的模型时。

```bash
# 1) 只出下区的提示词（同母版自动派生，无需维护第二份模板）
python3 scripts/build_prompt.py --part lower --title "Pasture" \
  --subject "..." --palette "..." --notes "03" --extra "..." > lower.txt
# 2) 用 lower.txt 走生成，尺寸取 3:2（如 1536x1024）。不要传参考图。
# 3) 合成（自动把上区裁切对准主体、自动抹水印）
node scripts/compose_halves.js --photo 原图.jpg --illustration 模型图.png --out 成品.png
```

`compose_halves.js` 会扫描原图找出主体的纵向范围，自动把裁切窗口对准主体；可用 `--crop-y` 手工指定、`--ratio` 改整体比例、`--width` 改输出宽度。

**上区裁切的物理约束（走路线 B 时务必先算）**：上区是横向的（3:4 整图 → 上区 3:2），能容纳的源图高度 = 源图宽度 ÷ 1.5。竖构图照片若主体很高，可能装不下全部背景。例如 1200×1600 的静物照，3:2 窗口只有 800px，而主体占 784px——**刚好只装得下主体，装不下背景里的次要元素**。这是数学限制，不是参数没调好；遇到时优先保证主体完整，并主动告诉用户牺牲了什么。

| 宿主具备的能力 | 做法 | 保真度 |
|---|---|---|
| **A. 图生图 / 图片编辑**（首选） | 把原图作为参考图或编辑输入，附上装配好的提示词，宽高比设 3:4。上区能真正保留原照片 | ★★★ 最高 |
| **B. 仅文生图** | 先写一段极详细的照片描述（主体姿态 + 构图 + 光位 + 3–5 个色 + 质感），把描述塞进 `--extra`，再文生图 | ★★ 上区为「重绘仿真」，非原始像素 |
| **C. 无图像能力** | 只交付装配好的提示词文本，说明可粘贴到任意图像工具（GPT Image / Midjourney / 即梦 / Nano Banana 等） | — 交付 prompt |

- **B 级必须提前告知用户**：上区是模型重画的高仿版本，不是原始照片，细节保真度会下降。
- **文字渲染**：若宿主模型不擅长生成文字（标题糊掉 / 拼错），降级方案是让模型不写标题（`--notes -` + `--extra` 里禁止文字），改由具备图像合成能力的宿主后期叠字（sharp / ImageMagick / PIL 均可）。叠字时用细体、字距略松、贴留白边缘，不要压在主体上。
- **图生图强度**：走路线 A 时用 **high** 保住上区。下区会不会退化成照片，**主要不取决于这个参数**，而取决于提示词里那四条机制（近白影棚底 / 薄纸板基座 / 哑光材质 / 禁止景深虚化噪点）在不在。若四条都写了、下区仍照抄成照片，再降到 medium 重试一次即可。**不要**为了"让下区变插画"把强度压到最低——那会把上区一起牺牲掉。
- **输出**：成品图存到工作目录，文件名建议 `<title 小写连字符>-<原图名>.png`，然后用宿主提供的文件展示能力（WorkBuddy 用 `present_files`；其他 Agent 用等价的附件/图片回传）交给用户，并附上本次使用的标题与色盘，方便用户复用。

## 五、常见失败模式与修法

| 症状 | 根因 | 修法 |
|---|---|---|
| 下区**偏正面平视的扁平插画**，没有等距体积感 | 「isometric」只出现在名词位置，被后半段描述压过去 | 母版已写死「30° 等距轴测投影：体块同时露出顶面与两个侧面，禁止正面平视」；若仍偏平，`--extra` 再补「可见顶面与两个侧面 + 薄纸板基座 + 明确投影」 |
| 下区**偏扁平矢量插画**（描边色块风） | 提示词里出现了「扁平色面 / 扁平插画」这类词，或模型自行简化 | 母版已写「不得是扁平矢量插画（禁止色块描边风格）」。`--extra` 补「哑光实体模型，有真实体积与柔和棚拍光，不要描边色块」 |
| **下区退化成原照片的写实复制**（不是模型） | 缺"变成模型"的机制：没有影棚白底、没有纸板基座、没有禁止景深 | 先确认母版四条机制都在（近白影棚底 / 薄纸板基座 / 哑光 / 禁止景深虚化噪点），再 `--extra` 强调「下区是放在近白影棚里拍摄的实体模型，禁止镜头虚化与景深、禁止暗角与摄影噪点」；仍不行再把图生图强度降一档 |
| **基座缺失、太厚，或没有纸页层次** | 母版只说「纸面或微型基座」，过于模糊，模型自由发挥 | 母版已写死「很薄的层叠纸板，侧面露出一层层纸页般的叠压纹理」；`--extra` 可再补「板厚约为板边长的 1/12」 |
| **板顶面地形与原图不对应**（换了一处风景） | 地形继承没被强制 | `--extra` 补「板顶面必须是原照片那块地形的切片，保留同一道山坡轮廓、同一批树木与主体的相对位置」 |
| 上区被重绘、主体变形 | 生成强度过高 | 降到图生图中等强度（或只重绘背景区域）；提示词里强调「上区仅调色，像素级保留主体」 |
| 标题跑到上区、压住照片 | 文字落点未限定 | 母版已写「标题与编号放在下区留白区域，紧贴水平分界线下方，不得压在照片区之上」；`--extra` 可再指定具体位置（如「贴下区左上角留白」） |
| 标题与编号挤在一起、字号过大，或**编号换行到标题下方** | 排版间距与同行约束未限定 | 母版已写「处在同一水平基线上、在同一行内左右排开，编号不得换行到标题下方」；还不行就 `--extra` 补「编号与标题的水平间距约为标题字宽的 2 倍，二者基线与字号保持一致」 |
| 下区颜色跳到固定色系（蓝紫/黄绿撞色） | 色盘没被强制 | 把 `--palette` 写成具体色相组合，并保留模板里的「不得引入色盘外颜色」一句 |
| 两区高度不等、明显偏移 | 对半约束不够硬 | `--extra` 加「分界线精确落在画面正中垂直中线上，误差为零」 |
| 文字糊掉 / 拼写错误 / 出现乱码 | 模型文字能力弱 | 见上节降级方案；或把标题缩到 1–2 个词 |
| 下区主体认不出 | 概括过度 | `--subject` 里点明 1–2 个识别特征（帽檐 / 发型 / 车头 / 旗杆 / 窗型 / 斑纹） |
| 出现第二个视觉中心 | 辅助元素抢戏 | `--extra` 加「辅助元素体积不超过主体的 1/5，且不构成第二焦点」 |
| 下区凭空多出人物/品牌 | 模型自由发挥 | `--extra` 加「只允许出现照片中已有元素，禁止新增人物、文字道具、品牌标识」 |
| 顶部/底部被裁掉 | 画幅不匹配 | 换合适 `--variant`，或让模型「自然延伸天空或地面」补足画幅 |

## 六、交付前自检清单

- [ ] 两区高度严格对半，分界线落在画面正中
- [ ] 上区主体与原照片一致，无变形、无拉伸、无重绘痕迹
- [ ] **下区是哑光的实体模型**——不是扁平矢量插画，也不是照片的直接复制
- [ ] **基座是一块很薄的层叠纸板**，侧面能看出一层层纸页般的叠压纹理
- [ ] **板顶面沿用原照片那块地形**（同一道山坡轮廓、同一批树木与主体的相对位置）
- [ ] **背景是纯净近白纸色**，板下只有一层紧贴轮廓的收敛接触阴影
- [ ] 下区一眼可辨是同一主体，姿态 / 朝向 / 斑纹与上区对应
- [ ] 色盘完全来自原图，无外部固定色系入侵
- [ ] 无卡通感、无扁平插画感、无塑料 3D 感、无高饱和撞色、无电商模板感
- [ ] 标题拼写正确、细体衬线、首字母大写；与编号之间拉开明显间距；不压在照片上
- [ ] 画面留白充足，下区不拥挤，无第二个视觉中心
- [ ] 无水印、无硬边框、无拼图式分割线

## 七、不花额度的后处理修补

生成结果上偶发的瑕疵，**不要重跑重生成**（每次都消耗额度），尽量在本地修掉。

### 1. 平台水印（几乎必有）

用 `scripts/patch_watermark.js`，见 SKILL.md 第 5 步。核心是别裁切——裁切会让 3:4 失衡、分界线不再居中。

### 2. 标题下多出一条装饰横线

模型偶尔会把「沿水平轴线排列」理解成画一条装饰线。母版已加「标题与编号下方不得加下划线、装饰横线、边框或色块底衬」，但**实测仍会偶发**。用 `scripts/patch_rule.js` 一键修掉：

```bash
# 只检测，先看命中位置
NODE_PATH=<sharp 所在 node_modules> node scripts/patch_rule.js --in 生成图.png --detect
# 确认无误后修补
NODE_PATH=<sharp 所在 node_modules> node scripts/patch_rule.js --in 生成图.png --out 成品.png
```

脚本自动完成「定位 → 扩张修补带 → 逐列插值重建 → 横向羽化」，背景是平滑近白渐变，修完肉眼无痕。

**这个坑比看起来深，四条经验都是踩出来的，不要绕开脚本手写：**

1. **不能只看「某行暗像素占比 > 85%」**。装饰线是**抗锯齿**的：只有中间 1 行是深灰（覆盖率≈1），上下各 1~2 行是浅灰软边，覆盖率可能低到 0.2~0.3。只认高覆盖率行 → 只补中间那行 → 上下留一条淡残影，肉眼仍可见。脚本因此分两层判据：`core`（高覆盖率，确定是线）+ `edge`（低覆盖率但跨度接近，软边）。
2. **真实影响范围比线芯宽**。实测一条线芯 3 行的线，光晕实跨 7 行（线芯 891–893，光晕 889–895）。所以必须 `expandBand` 向上下扩张成修补带。但扩张有风险——可能吃进标题文字或沙盘体块，因此**只沿背景行扩张**（该行跨度内白像素占比 ≥ 0.5 才算背景），一遇到有内容的行立刻停手，供体行取自扩张带之外 3 行。
3. **羽化遮罩的横向、纵向距离必须分开算**。曾经写成 `dx = min(左右距离, 上下距离)`，而线只有 3 行时上下距离恒为 0，alpha 被算成 0 → 首尾行整行透明 → 又是「只补中间一行」的假象。装饰线本身很薄，纵向不需要羽化（接缝靠邻行插值已经连续），只对左右端做横向羽化。
4. **阈值必须自适应**。以图**下半部分**亮度中位数为背景基准，取 `bg-16` 为暗阈值、`bg-8` 为近白阈值。固定阈值会被纸纹背景整片误判——纸纹本身就能暗到 200 以下。
5. **再加一条孤立性判据**排除误伤：线体之外的上下各 3 行，在**同一跨度内**必须几乎全白（≥90% 近白）。这一条把沙盘边缘、投影、草地等大面积暗区挡在外面。四条判据（实心 + 薄 + 孤立 + 自适应阈值）必须同时满足才算装饰线。

> 注意：在标度正确的成品上，**分界线精确落在 `y = 高度/2`**（1152×1536 时即 `y=768`）。检测装饰线时脚本只在分界线以下（`H/2 + 6`）搜索，先确认分界线位置再判读检测结果。

### 2.5 分界线的自动核验（用来确认「不是线，是照片本身的亮部」）

扫描「首个持续近白行」时会**误报**：若上区照片底部本身是大片亮部（黄昏水面亮度可达 200~211），会被当成下区的近白背景，读出一个偏小的分界值（实测 02-harbour-dusk 报出 43.4%）。正确做法是**看跃变而不是看绝对值**——在全分辨率下逐行打印 `y=740..800` 的亮度，`y=768` 处从 ~204 跳到 ~223，才是真分界。别被自动扫描的百分比误导。
